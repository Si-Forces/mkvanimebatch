# PR #219 verification

Base: `601bba16762a18a4ba924eebabeae7ac67213b27`. This record accompanies the
home-path gate and its regression tests; it is not part of the agent runbook.

## Reproduce

The project requires Node 20+. These measurements and the manual mutation audit
use Linux, GNU time and GNU timeout. The hook tests need Bash 4.4+; the scanner
itself targets Bash 3.2+.

The final local Node run passed all 227 tests with no failures or skips.
JavaScript and Bash syntax checks and `git diff --check` also passed.

```sh
node --test scripts/*.test.js desktop-tauri/ui/*.test.js
node scripts/home-path-mutations.js
node scripts/bench-home-path.js > memory.json
```

The mutation command prints its temporary result directory, retains a baseline
log and individual logs, and writes `results.json`. An optional mutation-ID
substring selects a smaller rerun. Every edit must match its source exactly once,
parse as Bash, and select an active test. A syntax error is not counted as a
caught regression. GNU timeout bounds nonterminating mutants and their children;
timeouts are reported separately from failed assertions. Production files are
never mutated.

The executable inventory is
[home-path-mutations.json](../../scripts/test-support/home-path-mutations.json).
Each entry gives the changed expression, replacement, selected test and expected
outcome. Surviving cases require a concrete reason.

## Mutation results

The complete audit on 2026-11-13 ran 208 independently edited cases: **195 failed
assertions, one bounded timeout, 12 expected survivors and no unexpected
outcomes**. The timeout removes progress from the ancestor walk; it is not counted
as an assertion failure. The unmodified selected suites passed first.

Method: [bench-home-path.js](../../scripts/bench-home-path.js) creates exact
128-byte added records for stdin; headers add 71/72 bytes to the 10/80 MiB
payloads. Real Git histories alternate two 256-line blobs in 160/1,280 commits.
Their 10/80 MiB labels are nominal patch targets; the table records the actual
rendered patch sizes. `git fast-import` creates them before timing. File creation,
import and patch-size measurement are outside the timed invocation.

Each invocation uses `/usr/bin/time -q -f '%M\t%e\t%x'` around Bash and the
scanner. Stdin is a file descriptor; reports go to `/dev/null`; published mode
scans `0..tip` without a named remote. Clean/refusing exit codes are checked.

GNU time's `%M` uses maximum resident-set accounting for the invocation and its
waited descendants. It is **not** the sum of simultaneous pipeline-process RSS.
The Node encoder's startup peak can dominate smaller awk allocations; flat
figures alone do not prove aggregate constant memory. The source retains current
line/filename/identity state and streams findings; the open-stdin regression
separately detects whole-report buffering. Git producers and individual long
lines have their own memory costs. See [GNU time](https://www.gnu.org/software/time/manual/html_node/Memory-Resources.html)
and [Linux resource accounting](https://man7.org/linux/man-pages/man2/getrusage.2.html).

## Limits of this verification

- Native Bash 3.2, BSD awk, Windows Git Bash and MSYS argument conversion were not
  executed locally. POSIX fixtures simulate Windows spellings; they do not prove
  native drive handling. `BASH_COMPAT=42` tests one expansion quirk, not an old
  Bash executable. Platform-only survivors are identified in the manifest.
- Local Turkish locales are installed; locale and invalid-byte fixtures run with
  byte-oriented awk behavior. Permission fixtures are conditional when run as
  root. jj fixtures require jj and report a skip if it is absent; they executed
  locally with jj 0.46.0.
- `/dev/full` is Linux-only; the corresponding write-failure fixture is explicitly
  skipped elsewhere. Raw POSIX byte-255 filenames are skipped on Windows.
- Inputs are not exhaustively enumerated. The inventory covers nontrivial guard
  families and failure routes, including boundary mutations and stated
  equivalences. It does not certify all possible tool versions or malformed
  inputs.
- Filename-only rejection (#226), PR text (#227), messages (#220), and binary
  merge/jj gaps (#222) remain separate tracked constraints.
