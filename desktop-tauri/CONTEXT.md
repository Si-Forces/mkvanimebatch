# Desktop Application Context

The desktop GUI host for anime fansub collections: it presents the queue, drives preflight inspection, and orchestrates a single batch execution. It owns presentation and user configuration, and owns no decision about what ends up in an output file.

## Ubiquitous Language & Explicit Prohibitions

| Canonical Domain Term | Definition | Prohibited Synonyms (Explicitly Avoid) |
| :--- | :--- | :--- |
| **Queue Tracker** | The state machine managing batch item lifecycles (`queued` → `processing` → `completed` / `skipped` / `planned` / `error` / `cancelled`), strictly keyed by item ID, together with each mode's Queue Selection and Track Assignments. The Desktop Core owns it (ADR-0016); the view only renders it and sends Intents. | Task list, item manager |
| **Desktop Core** | The toolkit-agnostic owner of all desktop UI state except the theme, which stays with each view: per mode the Inspection Manifest, Queue Selection, Track Assignments, Settings Draft and Run Log, plus the Job Snapshot and the Job Coordinator's phase. It contains the Engine Bridge, runs preflight and builds the Batch Request (a view never builds one), derives every displayed value (the status labels and tones, the elapsed times and the batch clock, the counts, the Episode Inspector and the job controls' texts), runs the Presentation Heartbeat and accepts Intents; a view only renders what it publishes. It lives as long as the process, so a view that reloads loses only its own view-local state, such as an open drawer or a scroll position. | View model, frontend store, app state |
| **Intent** | One input a view sends to the Desktop Core through `dispatch`: a user action (scanning a directory, ticking or reordering an episode, picking the episode the Episode Inspector shows, assigning or clearing a Track Assignment, editing or stepping a Settings Draft field or picking its Preset Profile, running or stopping a mode's batch, clearing the inspection cache), or a fact only the view knows, such as a picked path or whether the window is visible. A view changes no queue, Settings Draft, Run Log or job itself; it only sends Intents. | Command (a Tauri term), action, message |
| **Engine Bridge** | The in-process integration layer connecting the desktop to the Media Engine's Batch Pipeline, with task-level panic isolation, dual event and log streaming, and cooperative cancellation. | Wrapper, helper, controller |
| **Job Slot** | The Engine Bridge's single reservation for the one job the app runs at a time. It is reserved before the Job Snapshot begins, and refused while a job runs or stops and after shutdown has begun. Only the job's supervisor releases it, after `job-done`. Stop cancels the job cooperatively, waits 2 s, then aborts its pipeline task. | Job lock, run mutex, active flag |
| **Job Coordinator** | The Desktop Core's state machine owning the one job the app runs at a time across the Remux and Extract views (`idle`, `starting`, `running`, `stopping`) and the mode that owns it. It moves that state only through its named transitions. Run and Stop are Intents: a Run builds the Batch Request from the mode's Settings Draft and preflights the captured Queue Selection before it launches; a Stop cancels a start or stops the job. While a start or a job holds it, both queues and both Settings Drafts are locked. The view only renders it. | Job runner, execution manager |
| **Inspection Coordinator** | The Desktop Core component that runs Directory Inspections off the actor and deduplicates them: concurrent scans of the same Directory Identity and cache setting share one in-flight inspection, a forced scan always starts a fresh one, and one inspection runs at a time across both modes. | Scan manager, folder inspector |
| **Directory Identity** | The display form of a directory's canonical path, produced only by the Engine Bridge: the Inspection Manifest's `canonical_dir`, a published ModeView's `directory`, and the `input_dir` of the Job Snapshot and `BatchStart`. The Desktop Core and the UI compare identities byte for byte and never normalize a path themselves. | Normalized path, directory key |
| **Presentation Heartbeat** | The Desktop Core's single once-a-second tick that advances the elapsed time of every processing episode row at once, and on the same tick advances the bottom bar's batch clock. It runs only while the batch clock runs (while an Active Batch is executing) and the window is visible; showing the window again brings both up to date at once. | UI ticker, card timer, interval loop |
| **System Telemetry Provider** | The host probe reporting system CPU and memory usage and the disk write rate of the desktop process and its media tool child processes. It reports load only and recommends no concurrency settings. The Desktop Core owns it and samples it every second while a start or a job holds the batch and every 30 seconds otherwise, never while the window is hidden; a sample is taken at once when the window shows again or the batch is taken or released, and one never overlaps another. | Hardware probe, system monitor |
| **Run Log** | Each mode's log in the Desktop Core: the newest 2000 Log Channel lines of that mode's jobs, and the lines the core writes itself (a refused or failed Run, the wait for a Stop, a failed teardown, an inspection cache clear). A Run clears it once its request resolves, so a Run refused before that is logged under the earlier lines. It outlives a view, so a view that reloads shows it again. | Console buffer, log ring |
| **Job Snapshot** | The in-memory projection of one Active Batch — its participating items, progress, and outcomes, and the Effective Settings it runs with — held by the Desktop Core (ADR-0016), which publishes it as the View State's Job View. Queue rows lay it over the Inspection Manifest's order of its own mode; it never contains unselected Inspection Manifest items. | Job state, queue cache, execution status |
| **Card Progress** | The visual state of one active item in the Queue Tracker, drawn as the status ring of its episode row: indeterminate while starting up or transcoding, determinate once streamed item progress arrives. | Loading bar, queue spinner, progress gauge |
| **Library** | The sidebar section listing the scanned input directory and its release subfolders, each with its episode count. Picking a release scrolls the episode list to that release's group. It shows the scan; it decides nothing. | File tree, folder browser |
| **Episode Inspector** | The right-hand pane showing one episode's output, its subtitle precedence ladder with the Track Assignment controls, and its fonts. The Desktop Core derives what it shows, and picking its episode is an Intent. Batch settings are not here; they live in each mode's settings sheet. | Details panel, sidebar; never "folder inspector", which names a scan component |
| **Settings Draft** | One mode's batch settings as the user typed them in its settings sheet, before any run reads them: the folders, the concurrency fields, the run options and, for remux, the encode and its Preset Profile. The Desktop Core holds it and a view only mirrors it; it is not kept across launches. | Form state, settings model, config |
| **Queue Selection** | The user-marked subset and ordering of scanned manifest items chosen for execution. | Checked items, run list |
| **Active Batch** | The ordered Queue Selection submitted for one execution, excluding every unselected manifest item. | Entire scanned queue |
| **Item Settlement** | When a job ends, the Engine Bridge gives a terminal Item Outcome, through an ItemComplete, to every item of the Active Batch that the Batch Pipeline left open: cancelled when the job was stopped, otherwise error with the run's own failure message. Outcomes the Batch Pipeline itself gives (such as a planning failure, or an item it ends as cancelled on seeing a stop) are not Item Settlement. | Finalize, cleanup, close-out |

**Inspection Manifest**, **Preset Profile**, **Effective Settings**, **Item Duration**, **Batch Request**, **Track Assignment**, **Batch Item Info**, **Item Outcome**, and **Job Event** are owned by the [Media Engine context](../crates/mkv-core/CONTEXT.md) and consumed here. This context deliberately holds no second definition of them — see [ADR-0008](../docs/adr/0008-typed-engine-bridge-and-track-assignment-model.md) for why one owner, not two, keeps them honest.

**Native Package** and **AppImage** are packaging formats rather than components of this context, so they are deliberately kept out of the table above. They are load-bearing here — the split between them decides which GTK/WebKitGTK stack the process loads, and therefore which rendering workarounds apply — but the vocabulary and its rationale live in [ADR-0015](../docs/adr/0015-per-package-webkitgtk-dmabuf-renderer-scoping.md).
